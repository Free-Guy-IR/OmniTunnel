ip tunnel · disguised as ping

Every protocol gets
throttled. Echo

OmniTunnel carries ordinary IP traffic — TCP, UDP, anything — wrapped inside genuine ICMP echo request/reply packets, for links where everything else gets an initial burst through and then goes silent, but a plain ping keeps working the whole time.

install — run on each box 
curl -fsSL https://raw.githubusercontent.com/Free-Guy-IR/OmniTunnel/main/install.sh -o /tmp/omnitunnel-install.sh && sudo bash /tmp/omnitunnel-install.sh

One command. Downloads the tool, drops you into the setup wizard. If raw.githubusercontent.com is itself filtered, add --socks5 host:port to the second command.

outer wire — what the path actually sees type 8 / type 0 only
the problem

A burst gets through. Then nothing.

On some paths, TCP, UDP, GRE, and TLS relays all behave the same way: a short initial burst of data goes through, then the connection goes completely silent — no RST, no ICMP-unreachable, just gone. Bare ICMP keeps passing under the exact same conditions.

tcp / udp / tls relay

Burst of packets, then silence for the rest of the connection's life.

icmp echo

Steady request/reply, indefinitely, at full volume.

the evidence

Nothing wins everywhere. So measure it.

The manager builds every transport end-to-end against your own foreign box, measures both directions with parallel streams, tears the test tunnels down again, and ranks what survived. Two real captures, two completely different answers — which is the whole point.

One sustained flow uploads at 185 Mbit — but the moment real users open eight at once the aggregate collapses to 21.8. reverse-mux funnels every connection into a single flow, so the policer never sees the parallel burst it punishes: 226 Mbit at 8 streams, 240 at 32 — a ~10× upload difference on the same link. On this same path raw ICMP echo-request was 100% dropped while echo-reply passed untouched.

Both tables came straight out of omnitunnel bench. Your link will land somewhere else — run it, keep the winner, re-run it whenever conditions change.

how it works

Genuine echo semantics, not a raw shortcut

Both ends run the same binary. The envelope is deliberately asymmetric, because some paths police ICMP by direction as well as protocol.

01

Client always sends type 8

A genuine Echo Request, addressed to the peer's real IP — indistinguishable on the wire from a normal ping.

02

Server always answers with type 0

A real Echo Reply. Paths that permit "a reply to my own request" while treating an unsolicited inbound request as a fresh connection never see the difference.

03

Per-flow reordering restores order

Each inner packet's own 5-tuple keys its own small reorder buffer, so one connection's reordering event can never delay an unrelated flow — including a bare health-check ping.

04

Plain IP underneath

The payload is a full IP packet, so ordinary iptables DNAT port-forwarding works with zero protocol-specific code once the interface is up.

plain IP packets in, genuine-looking ICMP out — either direction
capabilities

Built for running it for real, not just a proof of concept

self-contained

Owns its own interface

Brings the TUN device up and assigns its point-to-point address from inside the process — no external ip addr/ip link calls before or after starting it.

reordering

Per-flow, not shared

Reordering on the underlying path is corrected per connection, keyed by each inner packet's real 5-tuple — one flow's hiccup can't delay another's.

port forwarding

TCP + UDP, together

Add, remove, and list forwarded ports through a proper DNAT + MASQUERADE chain, fully isolated in its own custom iptables chains.

safety

Conflict detection

Warns before adding a forward if another rule or a local listener already claims that port — the exact failure mode that once broke this silently.

multi-instance

More than one tunnel per box

Several Iran-side servers into one foreign box, or the reverse — each instance gets its own config, binary, systemd unit, and chains.

operations

systemd-native, no PID file

Type=simple; the binary is fully self-configuring, so systemd's own process tracking is always accurate.

reference

Usage

Running with no arguments opens the interactive menu — the normal way to use it day to day. Every action is also a direct subcommand for scripting.

# day to day omnitunnel # interactive menu omnitunnel bench # measure every transport, both directions omnitunnel list # tunnel health, rtt, loss omnitunnel pf-add main both 8080 # tcp+udp, forwarded to the far side omnitunnel pf-del main 8080 omnitunnel mux-add main 443 127.0.0.1 443 # single-flow muxed forward # a second, independent tunnel on the same box omnitunnel add-auto gre second <foreign_ip> omnitunnel add-manual gre second <foreign_ip> # no SSH: prints a token to paste abroad
